# 随身工具箱开发交接

审阅基于 `ccr-75ff76be-rli4x3` 分支的提交 `a92d1f2`。下列改进待实现。呼吸冥想和像素宠物已在另一份本地构建中启用，该构建已刷入并进入 `app_main()`，菜单导航和应用交互仍待真机验收。

## 1. 保留上次有效天气

天气页目前只把响应放在内存里，收到 HTTP 200 就覆盖。离线重启后没有可显示的数据，响应不完整时也可能覆盖有效缓存。参阅[天气页](../../main/app_clock.c)和[存储接口](../../main/esp_sys.c)。

- 把带版本号的天气快照写入持久存储，包括来源地点、数据时间、实况和带日期的预报。首次联网请求前先恢复快照。替换前校验长度和必需字段，仅在数据有实质变化时写入。
- 超时、断网或响应异常时继续显示快照，标注离线或过期，保留真实城市和更新时间。更换地点时，旧数据继续带原城市标签，直到取得新地点的有效天气。
- 让设备直连和中转使用一致的地点选择，或明确显示当前来源。设备直连读取本机设置，中转读取自己的 `[location]`。 [设备直连](../../main/esp_local.c) · [中转配置](../../server/config.example.toml)

**验收。** 成功获取一次天气后，断开 Wi-Fi 并重启，设备仍显示上次有效天气和日期。接收到异常响应时保留快照。恢复网络或切换城市后，取得有效响应才更新卡片。

## 2. 扫码菜单分开操作，支持保存多个 Wi-Fi

目前所有设置共用一个表单，页面在写入存储前就提示已保存。尝试连接新网络前，设备会覆盖唯一一组已保存的账号。参阅[门户与联网任务](../../main/esp_net.c)、[设备设置页](../../main/app_settings.c)和[设置存储](../../main/settings.c)。

| 菜单 | 操作 |
| --- | --- |
| 无线网络 | 显示当前连接、已保存和附近网络。支持重新扫描、手动输入隐藏网络、连接并保存、更换密码和忘记网络。 |
| 语音助手 | 选择模式，测试识别和对话，试听音色，单独保存语音设置。 |
| 天气位置 | 选择自动定位或指定城市，提供保存位置和刷新天气。 |
| 更多设置 | 中转地址、家庭助手和日历分别保存。 |
| 完成配置 | 结束配置会话并关闭热点。各分区保存后可留在菜单继续操作。 |

- 建议首版支持保存五个网络，自动迁移旧版的 SSID 和密码。重连时优先尝试上次成功的网络，有限次失败后尝试其他已保存网络。连接稳定时保留当前网络。列表满时提示用户选一项移除。
- 试连凭据暂留内存，确认目标网络拿到 IP 后才保存。试连失败则恢复原网络。用操作 ID 对应本次请求和结果，区分连接成功与写入成功。
- 在设备端校验各分区的数据，把存储失败返回到页面。区分密码未填写和明确选择开放网络。临时配网热点使用密码，配置接口要求有效会话并限制在配网接口上访问。网页响应和日志不回传已存密钥。
- 连接和写入放在后台任务中处理。试连失败后保留配网页供用户重试。

**进度。** 已完成:最多保存五个网络，自动迁移旧版的单个 SSID 和密码([列表逻辑](../../main/wifi_list.c)，有主机测试);优先连最近连上的网络，连不上时换下一个已保存的网络，先试扫描里看得到的;新网络先试连，拿到 IP 才保存，失败则回到已保存的网络;配置页显示当前连接、可忘记的已保存网络和附近网络;无线网络、天气、语音和更多设置分别保存，设备写入存储后网页才显示已保存;完成按钮关闭热点;热点使用随机 8 位数字 WPA2 密码，显示在屏幕上并写进二维码;语音密钥不会用明文 HTTP 发往公网。待做:配置会话令牌、并发提交的操作 ID、列表满时提示用户选择而不是移除最久没用的网络、真机验收。

**验收。** 从已存一个网络的旧版升级，确认仍能联网。添加第二个网络，重启后两个都还在。让第一个网络离线，确认设备能自动连接另一个。输错新密码时，原有网络仍可用。单独保存天气或语音后，Wi-Fi 列表保持原样。用手机连设备热点检查添加、忘记和完成配置。

## 3. 让语音配置可验证

设备直连的识别、对话和朗读共用一套地址和密钥，播放端按 16 kHz PCM 处理。Mac 中转可以分别配置三个环节，目前能连上中转时会优先使用它。 [设备直连语音](../../main/esp_ai.c) · [中转语音处理](../../server/passport_server/assistant.py)

- 提供明确的 **Mac 中转** 和 **设备直连** 两种模式，显示当前使用的模式。中转模式把服务商密钥留在 Mac，扫码页负责测试中转连接。现有示例在 Apple 芯片 Mac 上用 `mlx_whisper` 识别，使用 macOS 的 `say` 和 `Tingting` 朗读，对话在 `[llm]` 中单独配置。 [中转配置示例](../../server/config.example.toml)
- 直连模式提供服务商预设和音色选择，预填经验证的识别、对话和合成模型。现有硅基流动预设使用 `FunAudioLLM/SenseVoiceSmall` 识别，音色为 `FunAudioLLM/CosyVoice2-0.5B:anna`。以配置账号的实际测试确认模型可用。 [识别接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post) · [朗读接口](https://docs.siliconflow.cn/docs/api/audio-speech-post)
- 自定义接口和模型 ID 放在高级设置，识别、对话和朗读分别验证。云端密钥通过 HTTPS 发送，并绑定服务商和地址。切换服务商时要求选择对应密钥，提供明确的清除操作。
- 校验返回的音频格式和采样率，必要时转换成设备支持的格式。提供短句试听。朗读失败时保留文字回复，并提示失败环节与原因，例如鉴权失败、超时、模型不可用或音频格式错误。

**进度。** 已完成:自动 / 只用中转 / 只用直连三种方式;对话和语音分开的接口与密钥;DeepSeek + 硅基流动、硅基流动、OpenAI、自定义四个预设;换接口时清除旧密钥;24 kHz 朗读重采样;设备和中转分步报错;先连接再开麦。密钥不再用明文 HTTP 发往公网。待做:配置页测试按钮和试听、真机验收。

**验收。** 每种支持的模式分别验证短句识别、文字回复和音色播放。无效密钥或不兼容音频应提示对应环节。切换服务商时须明确选择密钥，朗读失败时文字回复仍可见。

## 交付顺序

先做天气持久缓存，再做带访问保护的分区配置与 Wi-Fi 迁移，最后做语音预设和分步诊断。主机测试覆盖无效快照、Wi-Fi 迁移和回退，以及分区保存的行为。运行[仓库验证流程](engineering/build-and-test.zh_CN.md)，单独记录真机结果。

真机验收若需要保留 NVS 设置和缓存，确认分区兼容后用分段刷写。参阅[固件布局与数据规则](engineering/firmware-layout.zh_CN.md)。
