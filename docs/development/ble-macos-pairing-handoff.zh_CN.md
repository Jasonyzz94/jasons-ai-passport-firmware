## 原始故障

遥控页面将 NimBLE 启动为可连接的 BLE HID 键盘。macOS 能收到 `Passport-10C0` 的广播，其中包含 HID 服务（`0x1812`），RSSI 较强。Mac 可以建立 BLE 连接、发现 GATT 服务、识别键盘、订阅报告并接收通知。

但 macOS 同时报告 `lePaired=0`，且链路未加密。随后设备端主动断开，临时安全密钥被清除。因此“蓝牙设置”可能一直停留在“正在连接”，无法形成可绑定、可重连的 HID 设备。

**GATT 连接成功和出现 HID 通知，并不等于配对、加密、绑定或端到端键盘输入已经验收。** 不要仅凭 `retrieveConnectedPeripherals` 判断这类由系统持有的 HID 连接；还要结合蓝牙服务时间线和真实按键输入。

## 根因

### 1. 未启用 HID 安全要求

`sdkconfig.defaults` 开启了安全连接及绑定相关的运行时行为，但没有设置 `CONFIG_BT_NIMBLE_SM_LVL`，因此 ESP-IDF 使用 NimBLE 默认级别 `0`。

NimBLE HID 服务只有在 `BLE_SM_LVL` 为 `2` 或 `3` 时才添加加密读写标志。级别为 `0` 时，macOS 无需配对即可发现服务并订阅。

### 2. 应用未在连接后主动发起安全配对

[esp_ble.c](../../main/esp_ble.c) 中，`BLE_GAP_EVENT_CONNECT` 成功路径没有调用 `ble_gap_security_initiate()`。手机可能主动发起安全配对，而 macOS 可能等待加密要求，因此实现不能依赖某一种中心设备的行为。

### 3. HID 初始化重置 GAP 设备名

应用在 `esp_hidd_dev_init()` 之前设置 GAP 名称。ESP-IDF 的 NimBLE HID 初始化随后调用 `ble_svc_gap_init()`，把名称恢复为默认值 `nimble`。广播数据仍包含 `Passport-10C0`，所以 macOS 可能为同一设备显示不同名称。设备信息服务还报告了模型号 `NimBLE`。

## 已实施的修复

1. `CONFIG_BT_NIMBLE_SM_LVL=2` 要求 Just Works 加密链路，并保留安全连接、绑定和 NimBLE NVS 持久化。
2. 外设在连接后主动发起安全配对。[ble_sec.c](../../main/ble_sec.c) 的决策策略会在对端丢失密钥时删除本地旧绑定并重试一次，其他失败则断开。主机测试位于 `tests/test_ble_sec.c`。
3. 在 HID 初始化之后设置 GAP 设备名和键盘外观，DIS 型号设为 `Passport`。
4. 遥控器页面仅在链路加密后才显示“已连接”。
5. 保持现有单连接、内存、Wi-Fi 让出以及停止/重启生命周期约束。

## 已确认的真机结果

- 修复固件记录了 `链路已加密,已绑定`，确认已加密并完成绑定，而不只是 GATT 就绪。
- macOS 真实事件监听收到 `UpArrow`（键码 126）和 `Return/Enter`（键码 36），两者均有完整的按下和松开事件。
- Mac 还收到 `Right Command`（右 Command，键码 54）和 `Right Control`（右 Control，键码 62）的修饰键事件，Passport 串口中有对应的 HID 通知。
- 用户确认 `Right Command` 可以唤醒其语音输入流程。`Right Control` 也已送达，但没有唤醒该流程；这是应用快捷键不匹配，不是 HID 传输失败。
- 分段刷写后已保存的设置仍然存在。本次验收不包含一般 Wi-Fi 联网测试。

## 下键与语音键的含义

在编程助手模式下，下键默认作为可配置的语音键。当 **▼ 键用途 = 语音键** 时，短按和长按都会以按下、松开的形式表达所选修饰键，都不应预期产生 `DownArrow`。

- 如果需要下箭头，在模式选择页设置 **▼ 键用途 → 向下 ↓**。
- 在编程助手模式下，下键作为语音键时，**双击 ▲** 也会发送 `DownArrow`。
- **长按 OK** 发送 `Escape`，**短按 OK** 发送 `Return/Enter`。

语音输入是否启动由目标操作系统或应用决定。修饰键已经送达不代表一定唤醒：应用可能要求按住、双击、其他修饰键，或修饰键加字母的组合；系统听写也可能单独处于关闭状态。修改固件前，应先把 Passport 的动作与目标应用的实际快捷键对应起来。

## 剩余验收

- 将 **▼ 键用途 → 向下 ↓** 后，验证 macOS 收到真实的 `DownArrow` 事件。
- 按实际功能验证演示、媒体、修饰键组合和文本输入。
- 退出并重新进入遥控页面，重启 Passport，确认可以重连，且不会出现重复或陈旧记录。
- 在一个主机上忽略设备后重新配对，覆盖重复配对恢复；同时回归测试手机配对与输入。
- 在系统设备详情中重新检查运行时 GAP 名称和 DIS 型号；只有代码修复不能算显示验收通过。
- 在已知网络可用时，单独验证实际 Wi-Fi 联网。
